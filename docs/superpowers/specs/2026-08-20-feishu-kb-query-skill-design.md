# feishu-kb-query Skill 设计

- 日期：2026-08-20
- 状态：设计确认，准备实现
- 关联同步器：`feishu-kb-sync`
- 目标 Skill：`C:\Users\huchh\.agents\skills\feishu-kb-query`

## 1. 目标与边界

`feishu-kb-query` 是知识库生命周期编排 Skill，配合 `feishu-kb-sync` 完成：

- 从公开 GitHub Release 安装和更新同步器；
- 登记一个已经存在的飞书知识库；
- 强制用户提供知识库专属 Skill 简称；
- 在 query Skill 的同级目录生成 `feishu-kb-xxx`；
- 配置 Windows 用户级周期同步。

知识库查询由生成的 `feishu-kb-xxx` 承担。专属 Skill 只访问生成时指定的本地目录，不访问飞书、不检查同步器状态、不启动同步，也不读取其他知识库。

本次范围限定为 Windows。知识库创建指登记已有知识库，不在飞书侧新建知识空间。

## 2. 目录与数据归属

query Skill 本身位于用户指定的 Skill 根目录；生成的专属 Skill 与它共享父目录：

```text
<skill-root>\
├── feishu-kb-query\
└── feishu-kb-xxx\
```

同步器的共享配置继续保存在 Home 目录，供不同 Agent 复用：

```text
%USERPROFILE%\.feishu-kb-sync\
├── config.json
├── auth.json
├── schedule.json
├── cache\
└── logs\
```

query Skill 的编排注册表保存在：

```text
%USERPROFILE%\.feishu-kb-query\registry.json
```

注册表保存知识库名称、`space_id`、简称、专属 Skill 路径和 query Skill 路径。同步器配置仍由同步器自己维护，query Skill 不复制其配置模型。

## 3. 同步器 Release 生命周期

Release 仓库固定为：

```text
https://github.com/rj-huchaohong/feishu-kb-sync
```

每次显式运行 `feishu-kb-query` 时，立即使用当前可用同步器继续工作，同时后台检查 GitHub 最新 Release：

1. 读取 `releases/latest`；
2. 选择正式发布的 `feishu-kb-sync-v<version>.zip` 资产及其校验文件；
3. 比较本地版本；
4. 版本相同则复用；
5. 版本更新则下载到临时目录，校验包结构、版本和 SHA-256；
6. 安装到 query Skill 自身的版本化运行时目录；
7. 健康检查通过后原子更新当前版本指针；
8. 保留至少一个旧版本用于回退。

首次安装没有可用版本时，创建知识库或配置周期同步必须等待安装成功。后台更新失败不得影响当前版本继续使用。多个 Agent 同时触发检查时，使用 Home 目录锁避免重复下载。

稳定启动入口不随版本变化。Windows 周期任务调用稳定入口，由稳定入口转发到当前版本，避免任务绑定旧版本路径。

## 4. 知识库登记流程

用户登记已有知识库时必须提供：

1. 本地显示名称；
2. 飞书知识库链接或 `space_id`；
3. 专属 Skill 简称 `xxx`。
4. 每天同步时间，格式为 `HH:MM`。

简称不从名称、链接、`space_id` 或哈希值推断。默认只允许小写字母、数字和连字符。

流程：

```text
确保同步器可用
    ↓
检查认证或提示登录
    ↓
feishu-kb-sync config add <名称> <链接|space_id>
    ↓
校验简称并检查同级目录冲突
    ↓
写入共享注册表
    ↓
生成 feishu-kb-xxx
    ↓
启动首次后台同步
    ↓
    使用指定时间安装或刷新 Windows 周期任务
```

`feishu-kb-sync` 不接收 `--skill-suffix`，也不创建、更新或删除专属 Skill。

同步时间是全部知识库共用的全局设置。每次登记知识库都必须显式提供时间；如果已有全局时间，新提供的时间必须与其一致。需要变更时间时，必须通过单独的全局调度变更操作重新注册全部知识库的计划任务，不能在单个知识库登记流程中隐式改变其他知识库的调度。

## 5. 专属 Skill 生成规则

生成位置为 query Skill 所在目录的父目录下的 `feishu-kb-xxx`。专属 Skill 必须写入：

- 知识库本地目录的绝对路径；
- 只基于该目录回答的边界；
- 关键词初筛、候选文档收敛和局部阅读规则；
- 大 Markdown 文档的延迟目录提取规则；
- 来源引用、证据不足和冲突处理规则。

专属 Skill 不得：

- 调用 `feishu-kb-sync`；
- 检查同步状态或触发同步；
- 访问飞书或其他网络来源；
- 读取其他知识库；
- 在开始查询时打开全部 Markdown 文件。

同级目录已有但没有 query 托管标记时拒绝覆盖。已托管且 `space_id` 相同的目录允许更新；同一简称绑定其他 `space_id` 时拒绝操作。

## 6. 专属 Skill 查询规则

专属 Skill 采用两阶段本地检索：

```text
关键词扫描全库
    ↓
筛选少量候选文档
    ↓
仅对大候选文档提取 Markdown 目录
    ↓
按标题和行号读取相关章节
    ↓
必要时扩展相邻章节或少量文档
```

第一阶段允许用 `rg` 对全部 Markdown 做机器级文件扫描，但只输出候选路径、命中行和有限上下文，不把全库正文送入模型。没有 `rg` 时使用 PowerShell `Select-String` 备用。

第二阶段只对已筛选的大文档提取目录：通过标题标记获取标题行、层级和行号，根据下一条同级或更高层级标题确定章节范围；只读取相关章节，不因提取目录而读取整篇文档。小文档直接读取命中位置，不必提取目录。

本地 Markdown 是唯一事实来源。回答必须区分直接证据、跨段归纳和无法确认的内容，并为关键结论附本地路径。没有足够证据时应继续收敛或询问用户，不得通过全量读取弥补不确定性。

## 7. Windows 周期同步

query Skill 调用同步器的 Windows 用户级调度能力：

- 创建知识库时必须要求用户提供每天同步时间；
- 时间格式为 `HH:MM`，并通过 Windows 计划任务校验；
- 所有知识库共用一个同步时间；
- 首次登记时使用用户提供的时间安装计划任务；
- 后续登记必须提供相同的全局时间；
- 变更时间时重新注册全部知识库的计划任务；
- 调度范围为同步器已登记的全部知识库；
- 不需要管理员权限；
- 调度任务使用稳定启动入口；
- 安装后通过调度状态确认任务注册结果。

## 8. 错误与安全

- GitHub 不可访问：已有版本继续工作；首次安装明确失败。
- Release 资产缺失或校验失败：不切换当前版本。
- 同步器安装失败：不写入半成品版本指针。
- 知识库简称冲突：拒绝覆盖已有非托管目录。
- `space_id` 冲突：拒绝把一个简称绑定到多个知识库。
- 周期任务注册失败：保留知识库登记和缓存，不伪报成功。
- 专属 Skill 查询无本地证据：明确说明本地资料不足，不联网补充。

## 9. 验收标准

- `feishu-kb-query` 位于 `C:\Users\huchh\.agents\skills`，可被自动发现。
- 每次运行都会后台检查 GitHub 最新 Release，版本未变化时不重复下载。
- 首次运行能安装同步器并保留旧版本回退能力。
- 配置、认证、缓存和调度状态继续位于 Home 目录。
- 登记知识库时缺少简称或每天同步时间会拒绝继续。
- 同步时间格式非法或与现有全局时间不一致时会拒绝登记。
- 生成的 `feishu-kb-xxx` 与 query Skill 同级。
- 专属 Skill 只知道自己的本地目录和查询规则，不调用同步器、不联网。
- 查询先用关键词定位少量文档，再对大文档延迟提取目录，不全量读取知识库。
- Windows 周期任务可以注册、查询状态并同步全部已登记知识库。
